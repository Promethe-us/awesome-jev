A PRACTICAL START

先别急着接 API。

第一个问题选得小、状态足够清楚、错误可以回退，后面的评测和集成才有意义。

01 判断任务是否合适路由、筛选、排序、门控，还是需要生成文字？ → 02 在 Playground 看难例不是看一次成功，而是看缺信息、中文、否定与边缘情况。 → 03 跑通一个最小闭环SDK、低置信度回退、日志和独立验证集。 →

THREE BUILDING BLOCKS

先把问题写对。

CHOICE

从已知选项里挑一个

工单属于哪个队列？下一步调用哪个已有技能？

SCORE

落在有序等级的哪一档

风险、紧急度、相关性需要怎样分级？

NOUL

一个命题是否成立

需要人工复核吗？注意：没有独立 confidence 字段。

候选项和分级应该可观察、互相区分，并为无法判断的情况留下出口。阅读设计要点 →

A READING RULE

每个结果都问一句：
“它在什么条件下成立？”

链接可打开
不等于已经复现，更不代表能用于你的任务。

类型受约束
不等于判断正确；低置信度和错误案例要进入设计。

作者测得更快
不等于你的网络、输入、并发、模型版本和成本也一样。
