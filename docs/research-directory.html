  • 模型文档 ↗与 Jev 1.13 已知不足 ↗：确认当前能力和限制。

5. 正确理解概率与已知不足

↑

官方 Confidence 文档 ↗说明：Choice / Score 的 confidence 根据返回概率分布计算，概括分布集中程度；它不是单独向模型询问“你有多确定”的自由文本自评。Noul 不返回独立的 confidence。 高集中度也不自动证明现实任务上的高正确率。

官方 jaggedness 文档 ↗列出九类弱点：字面理解、数值计算、日期比较、多层间接推理、无关长上下文、对抗内容、指令与选项冲突、跨问题不满足预期恒等式，以及文本生成。例如，分别问两个互为否定的 Noul，返回概率未必相加为 1；不要把一个问题调好的阈值直接移到另一种问法。

“输出类型受约束”只缩小了答案空间，仍可能选错、受提示注入影响或遗漏关键上下文。把算术、时间比较、动作权限和业务不变量交给确定性代码；模型负责无法轻易写成规则的窄范围语义判断。

6. 复核新评测时至少记录这些信息

↑
  • 数据：独立样本数、语言、类别分布、标注人 / 模型裁判、训练与测试划分。
  • 版本：实际响应的模型 ID、SDK 版本、提示词和候选项；保留选项排列。
  • 质量：准确率之外，报告各类误判、拒答覆盖率与概率校准；小概率桶列出样本数。
  • 性能：端到端 p50 / p95、并发、输入长度、问题数、网络地区和本地硬件。
  • 成本：区分每 token、每请求、每问题；注明促销、重试和自托管估算。
  • 复现：链接原始结果与代码，记录失败案例；阈值在验证集调整，再用独立测试集确认。
